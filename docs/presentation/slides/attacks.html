• Left: the protocol from the previous slide. Right: each red arrow is an attack, pointing at the verifier check that rejects it. • Edit the record → step 5. The root hash commits to every value, and the random checks are derived from it. Editing anything afterwards changes the hash, so the old answers no longer fit. • Fake a calculation → step 6: a faked multiplication fails the random-vector checks. The same check catches reporting one batch while training on another, since the verifier rebuilds each step's inputs from the reported batch. • Retrying until the checks look lucky (grinding) is also covered by step 6: we use enough checks to survive about 2^52 retries, roughly what a well-funded research lab could afford. • Tamper with weights → step 7: the weight change is checked number by number against the training rule. • Use unagreed data → step 7: every record in a batch is checked against the agreed dataset's hash at its scheduled position. Step 7 also catches skipped, swapped or reordered steps, since each step must start exactly where the last one ended. • Swap the model → the global check: the first model must be the agreed base model and the last must be the one actually deployed. • Bottom line: a cheating run gets through with probability at most about 1 in 30 million (2^-25), even counting retries. • Not covered, by design: we prove the agreed recipe was followed on the agreed data. If the agreed data or recipe is itself bad, honest training on it passes. Very small changes (below a floor set by rounding noise and the number of checks) aren't guaranteed to be caught.
